# osu!Collector Downloader — локальное веб-приложение

Приложение на Node.js открывает локальную страницу, получает публичный список наборов карт из osu!Collector и загружает `.osz` с публичных зеркал osu!. Вход в аккаунт, cookie и OAuth для загрузки не нужны. Внешние npm-пакеты не нужны. Оно слушает только loopback-интерфейс `127.0.0.1`, поэтому страница не доступна другим компьютерам в сети.

## Запуск

Нужен Node.js 20.3.0 или новее (проверено с Node 24). В папке проекта выполните:

```sh
npm start
```

Либо без npm:

```sh
node server.js
```

Откройте в браузере адрес, указанный сервером — по умолчанию `http://127.0.0.1:3000`. Чтобы выбрать другой порт: `PORT=3100 npm start` (PowerShell: `$env:PORT=3100; npm start`). Чтобы остановить сервер, нажмите `Ctrl+C`.

После запуска подробные структурированные логи выводятся в консоль IDE/терминала, где выполняется `npm start`: старт и порт сервера, запросы API, получение коллекции, создание/завершение задачи, каждый набор, редиректы, пропуски и ошибки с HTTP-статусом. Значения cookie, Client Secret и OAuth-токенов в логах не выводятся. Каждая запись — JSON с временем, уровнем (`info`, `warn`, `error`) и событием.

Вставьте ссылку на коллекцию и нажмите **Показать карты**: приложение покажет названия, исполнителей и мапперов наборов в вертикальном прокручиваемом списке. По умолчанию выбран способ **Зеркала**: файл запрашивается у `osu.direct`, при неудаче — у `Hinamizawa`, затем у `osu!dl`; размер файла известен, поэтому виден прогресс в байтах и процентах. Если набор не найден ни на одном зеркале, можно добавить cookie `osu_session` — тогда загрузка идёт напрямую с osu!. Во время загрузки отображаются общий прогресс коллекции, прогресс текущего файла в байтах, процентах и объёме, а также зеркало, с которого качается файл. Файлы появятся в папке `downloads` рядом с проектом; имена — `{beatmapset_id}.osz`. Уже существующие непустые файлы пропускаются, между новыми загрузками выдерживается пауза 1.1 секунды.

Пример коллекции: [stream 180–189](https://osucollector.com/collections/23905/stream-180-189).

## Способы загрузки

**Зеркала (по умолчанию).** Используются публичные зеркала osu!, порядок: `https://osu.direct/d/{id}` → `https://mirror.hinamizawa.ai/api/v1/hinai/d/{id}` → `https://osudl.org/s/{id}`. Порядок задаётся массивом `MIRRORS` в [server.js](server.js). Для каждого набора приложение пробует зеркала по очереди; ответ проверяется по ZIP-сигнатуре, поэтому HTML-страница или JSON ошибки не будут сохранены как `.osz`. Редиректы зеркал разрешены только на https-хосты (IP-адреса и локальные имена отклоняются), учётные данные на зеркала не отправляются. Это сторонние сервисы: набор может отсутствовать, зеркало может быть недоступно или ограничивать частоту запросов — поэтому и есть резервные варианты.

**Ограничения частоты (HTTP 429).** Если зеркало отвечает `429`, приложение читает заголовок `Retry-After` (секунды или дата) и ставит это зеркало на паузу — по умолчанию 60 секунд, максимум 15 минут. На время паузы зеркало пропускается (в логе — `map.download.mirror.skipped`), загрузка сразу продолжается с другого. В карточке «Скачивание» есть панель «Зеркала»: у каждого источника показано «доступно» или «пауза N с» с посекундным отсчётом; статус подтягивается с `GET /api/mirrors` раз в 4 секунды. Такой ответ **не считается ошибкой набора**: карта не попадает в счётчик ошибок, а пробуется на следующем зеркале. Если ограничены все зеркала сразу, приложение ждёт ближайшее освобождение, только когда до него не больше 30 секунд, и повторяет попытку. Если и это не помогло, загрузка ставится на паузу: такой набор не попадает в счётчик ошибок, очередь останавливается.

**Автовозобновление.** Приостановленная из-за лимитов задача больше не ждёт ручного вмешательства: сервер планирует её продолжение на момент, когда остынет ближайшее зеркало (плюс 1 секунда запаса), и запускает ту же задачу сам — в логе это `download.job.auto_resume.scheduled` и `download.job.auto_resumed`. В статусе загрузки при этом видно обратный отсчёт «Автовозобновление через N с», а кнопка «Остановить» остаётся доступной, чтобы прервать ожидание; «Продолжить» на время автопродолжения скрыта. Уже скачанные файлы пропускаются. Если зеркала снова ответят `429`, пауза и планировщик повторятся, но не больше 8 раз на задачу (`download.job.auto_resume.exhausted`) — дальше остаётся ручная кнопка **Продолжить**. Она перезапускает ту же задачу (`POST /api/downloads/{id}/resume`), сбрасывает счётчик автопопыток и начинает счётчики заново; если нажать её, пока зеркала ещё остывают, сервер ответит `429` с остатком времени и задача останется на паузе. Продолжить можно и обычной кнопкой «Скачать наборы» — результат тот же.

**Cookie osu_session (резерв).** Официальный путь напрямую с osu!, если на зеркалах нужного набора нет:

1. Войдите на `https://osu.ppy.sh` в браузере.
2. В инструментах разработчика браузера найдите хранилище Cookies сайта и скопируйте значение `osu_session`.
3. Вставьте это значение в локальном приложении. Пароль osu! приложению не нужен.

Cookie — секрет, который даёт доступ к вашей сессии. Не отправляйте её другим людям, не публикуйте, не сохраняйте в исходниках и не вставляйте в сообщения. Приложение держит cookie только в оперативной памяти процесса Node.js (срок действия сессии — до 6 часов либо до перезапуска сервера): она не записывается в файл, очищается при остановке процесса и передаётся только на `osu.ppy.sh`. На ваш loopback устанавливается HttpOnly cookie с непрозрачным случайным идентификатором; cookie сессии osu! туда не попадает. При редиректе к настроенному osu! серверу загрузки cookie osu! удаляется. Очистить сессию можно кнопкой **Удалить**; выход из osu! также отзывает её.

**OAuth (скрыт и по умолчанию отключён).** Клиентская и серверная логика OAuth сохранена полностью, но отключена на сервере по умолчанию (флаг `ENABLE_OAUTH=false`) и скрыта в интерфейсе, так как osu! не разрешает обычному OAuth-приложению скачивать `.osz` (endpoint API загрузки помечен как `lazer`, стандартное приложение получает `403 Invalid scope(s) provided`). В отключённом состоянии эндпоинты `/api/oauth/*` и `/oauth/callback` отклоняют запросы для минимизации поверхности атаки. Для экспериментального включения:
1. Запустите сервер с флагом: `ENABLE_OAUTH=1 npm start` (PowerShell: `$env:ENABLE_OAUTH=1; npm start`).
2. В [index.html](index.html) уберите атрибут `hidden` у блока карточки OAuth и у `#option-oauth`.

Не публикуйте порт и не выставляйте приложение в интернет: локальный интерфейс специально рассчитан на доверенный браузер этого компьютера.

## Источники данных и ограничения

- Список коллекции берётся из публичного JSON osu!Collector: `GET https://osucollector.com/api/collections/{collection_id}`, где `beatmapsets[].id` — ID набора. Названия/исполнители получаются из пагинированного `GET https://osucollector.com/api/collections/{collection_id}/beatmapsV2?perPage=100` (курсор `nextPageCursor`); если этот endpoint недоступен, используются ID наборов.
- Файл запрашивается у публичных зеркал (см. раздел «Способы загрузки») либо, в резервном режиме, по официальному веб-маршруту `https://osu.ppy.sh/beatmapsets/{beatmapset_id}/download`. osu! проверяет сессию, права и лимиты учётной записи, затем перенаправляет на выбранный сервер загрузки. Недоступный или удалённый набор может завершиться ошибкой.
- Анонимные зеркала не связаны с osu! и могут меняться. Если ссылки перестанут работать, обновите массив `MIRRORS` в [server.js](server.js).
- Приложение только сохраняет `.osz` на диск. Импортируйте набор в osu! открытием файла либо штатными средствами клиента; приложение не изменяет папки игры и не устанавливает карты автоматически.
