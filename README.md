# osu!Collector Downloader — локальное веб-приложение

[![CI](https://github.com/kymifBSM/osu-collector-downloader/actions/workflows/ci.yml/badge.svg)](https://github.com/kymifBSM/osu-collector-downloader/actions/workflows/ci.yml)

Приложение на Node.js открывает локальную веб-страницу, получает публичный список наборов карт из osu!Collector и загружает `.osz` с публичных зеркал osu!. Вход в аккаунт, cookie и OAuth для стандартной загрузки не нужны. Сторонние runtime-зависимости отсутствуют (Zero-Dependency). Сервер слушает исключительно loopback-интерфейс `127.0.0.1`, поэтому веб-страница и API недоступны другим компьютерам в локальной сети.

---

## Запуск и требования

Требуется **Node.js 20.3.0 или новее** (проверено на Node.js 20, 22 и 24).

Запуск приложения:
```sh
npm start
```

Либо напрямую через Node.js:
```sh
node server.js
```

После старта откройте в браузере локальный адрес — по умолчанию `http://127.0.0.1:3000`.  
Чтобы выбрать другой порт:
```sh
# Linux / macOS:
PORT=3100 npm start

# Windows PowerShell:
$env:PORT=3100; npm start
```

Чтобы остановить сервер, нажмите `Ctrl+C` (выполняется корректное завершение с отменой задач и удалением временных файлов `.part`).

### Тестирование и проверка типов

В проект встроен тестовый раннер `node:test` и статический анализатор типов TypeScript/JSDoc (без этапа сборки):

```sh
# Запуск модульных и интеграционных тестов (60 тестов, 0 сторонних зависимостей)
npm test

# Статическая проверка типов через TypeScript компилятор
npm run check
```

## Способы загрузки карт

### 1. Зеркала (по умолчанию)
Используются публичные зеркала osu! со следующим каскадным порядком переключения:
1. `https://osu.direct/d/{id}` (`osu.direct`)
2. `https://mirror.hinamizawa.ai/api/v1/hinai/d/{id}` (`Hinamizawa`)
3. `https://osudl.org/s/{id}` (`osu!dl`)

**Параллельная загрузка (Worker Pool) и распределение нагрузки:**
- Скачивание beatmap-наборов с зеркал выполняется параллельным пулом воркеров (по умолчанию 3 воркера, настраивается через `DOWNLOAD_CONCURRENCY`).
- **Строгий лимит на зеркало (Per-mirror slot):** к конкретному зеркалу отправляется не более 1 одновременного запроса.
- **Интервал между запросами (Per-mirror delay):** между последовательными обращениями к *одному и тому же* зеркалу выдерживается пауза `DOWNLOAD_DELAY_MS` (1.1 с), что полностью исключает превышение лимитов и получение HTTP 429.
- Воркеры распределяются по доступным зеркалам со смещением (round-robin / work-stealing) и при занятости первого зеркала не блокируются, а сразу переключаются на свободное незаблокированное зеркало.
- Для авторизованных способов `session` и `oauth` (напрямую с `osu.ppy.sh`) в целях безопасности аккаунта всегда принудительно используется ровно 1 воркер.

**Режим скачивания «Без видео» (No Video):**
- В карточке «Скачивание» доступен чекбокс **«Скачивать без видео»**, выбор сохраняется в `localStorage` браузера.
- При включении чекбокса к запросам загрузки на зеркала и официальные эндпоинты добавляется параметр `?noVideo=1`.
- Режим сокращает трафик и используемое дисковое пространство на 70–80% (видеофайлы фонов занимают большую часть размера `.osz`), а предварительная оценка свободного места на диске снижается с 10 МБ до 3 МБ на набор.
- Во время активной загрузки переключатель блокируется, а в строке прогресса отображается индикатор `· без видео`.

Порядок и адреса по умолчанию заданы в [lib/config.js](lib/config.js). Вы можете переoпределить список зеркал через переменную `OSU_MIRRORS`:
- В виде JSON-массива: `OSU_MIRRORS='[{"id":"my","label":"My Mirror","url":"https://example.com/d/{id}"}]'`
- В виде списка URL через запятую: `OSU_MIRRORS="https://osu.direct/d/{id},https://osudl.org/s/{id}"`

**Ограничения частоты запросов (HTTP 429) и кулдауны:**
- Если зеркало возвращает `429`, парсится заголовок `Retry-After` (в секундах или в формате HTTP-Date). Зеркало ставится на паузу (по умолчанию 60 секунд, но не более 15 минут), а текущая карта немедленно запрашивается со следующего зеркала.
- Такой ответ **не считается ошибкой карты** и не увеличивает счётчик сбоев.
- В карточке «Скачивание» отображается статус каждого зеркала («доступно» или обратный отсчёт паузы). Во время активной загрузки статус зеркал и задачи транслируется в реальном времени через постоянный поток Server-Sent Events (SSE); в режиме ожидания при наличии кулдаунов — раз в 4 с через `GET /api/mirrors`.
- Если временно ограничены все зеркала, сервер ожидает до 30 секунд ближайшего освобождения прямо в сетевом цикле. Если пауза больше 30 секунд, задача автоматически приостанавливается (`status: "paused"`).

**Автовозобновление:**
- Приостановленная из-за кулдаунов задача автоматически возобновляется сервером в момент остывания ближайшего доступного зеркала (+1 секунда запаса). В интерфейсе отображается таймер «Автовозобновление через N с».
- Допускается до 8 автоматических попыток возобновления подряд (настраивается параметром `AUTO_RESUME_MAX_ATTEMPTS`). Если лимиты не сняты, остаётся ручная кнопка **Продолжить**.
- Кнопка **Остановить** доступна всегда, позволяя прервать как активную, так и приостановленную задачу.

### 2. Cookie `osu_session` (резервный способ)
Официальный маршрут загрузки напрямую с серверов `osu.ppy.sh` для редких карт, которых нет на зеркалах:
1. Авторизуйтесь на сайте `https://osu.ppy.sh` в браузере.
2. В инструментах разработчика (F12 $\to$ вкладка Application/Storage $\to$ Cookies) скопируйте значение cookie `osu_session`.
3. Вставьте значение в поле карточки «Cookie osu_session».

**Безопасность cookie:**
- Секрет хранится **исключительно в оперативной памяти** процесса Node.js и сбрасывается при перезапуске сервера либо по истечении TTL (до 6 часов). Значение никогда не пишется на диск.
- В браузер клиенту выставляется локальная сессионная `HttpOnly SameSite=Strict` cookie с криптографическим идентификатором; оригинальное значение `osu_session` в браузер не возвращается.
- Cookie передаётся строго на домены `osu.ppy.sh`. При редиректах на сторонние серверы загрузки cookie сессии удаляется.
- В любой момент сессию можно удалить кнопкой **Удалить**.

### 3. OAuth 2.0 (экспериментально, по умолчанию отключён)
В приложении реализован полный цикл osu! OAuth 2.0 (Authorization Code Grant), но по умолчанию эндпоинты закрыты флагом `ENABLE_OAUTH=false`, а блок скрыт в интерфейсе. Официальный веб-эндпоинт скачивания osu! закрыт скоупом `lazer` (стандартные OAuth-клиенты получают `403 Invalid scope(s) provided`).

Для экспериментального включения:
1. Запустите сервер: `ENABLE_OAUTH=1 npm start` (PowerShell: `$env:ENABLE_OAUTH=1; npm start`).
2. В [index.html](index.html) удалите атрибут `hidden` у блока `<section id="oauth-card" ...>` и у радиокнопки `#option-oauth`.

## Механизмы надёжности и безопасности

- **Защита от SSRF и DNS Rebinding:** При редиректах зеркал сервер проверяет целевой хост: выполняется асинхронный DNS-резолвинг (`dns.lookup`) с проверкой всех IP-адресов. Запрещены приватные подсети (RFC 1918), loopback (`127.0.0.0/8`, `::1`), link-local / облачные метаданные (`169.254.169.254`, `fe80::/10`), carrier-grade NAT (`100.64.0.0/10`) и любые порты, кроме 443.
- **Защита от CSRF и Fetch Metadata:** Запросы проверяются по заголовкам `Host`, `Origin` и W3C `Sec-Fetch-Site`. Запросы со сторонних сайтов отклоняются с кодом HTTP 403.
- **Защита от OAuth Login CSRF:** При старте авторизации генерируется одноразовый криптографический `nonce`, привязанный к `HttpOnly Lax` cookie.
- **Маскирование секретов в логах:** Все конфиденциальные данные (cookie, Client Secret, access/refresh токены) автоматически регистрируются в механизме санитизации и заменяются на `[redacted]` в консоли и текстах ошибок. Логи пишутся в структурированном JSON-формате.
- **Атомарная запись и верификация ZIP:** Каждый набор скачивается во временный файл `{setId}.{jobId}.part`. Перед переименованием в `.osz` файл проверяется на наличие сигнатуры EOCD (End of Central Directory) архива ZIP / ZIP64. Если зеркало вернуло HTML-страницу с ошибкой или файл повреждён, он отбрасывается.
- **Контроль дискового пространства:** Перед запуском очереди сервер оценивает недостающий объем данных с учетом уже имеющихся файлов на диске и проверяет доступное место через `statfs`. Если диск переполнится во время работы, очередь останавливается без потери уже скачанных файлов.
- **Дедупликация и кэширование osu!Collector:** Снимки коллекций кэшируются в памяти на 10 минут, а параллельные запросы объединяются (`in-flight join`), исключая лишнюю нагрузку на API osu!Collector.
- **Мгновенный старт и ленивая подгрузка названий (Lazy Metadata):** При запросе коллекции список `setIds` и карточка коллекции отдаются клиенту мгновенно (~150–300 мс) со структурой и базовыми названиями. Кнопка скачивания становится активной сразу, а детальные метаданные карт (`beatmapsV2`) пагинируются в фоне, плавно обновляя DOM на клиенте и активную задачу без блокировки и скачков скролла.
- **Повтор только ошибок (Retry Failed Only):** Если часть наборов завершилась ошибкой (`failed > 0`), в карточке скачивания отображается кнопка **«Повторить ошибки (N)»**. Серверный эндпоинт `POST /api/downloads/:id/retry-failed` ставит в очередь исключительно сбойные наборы без повторного скачивания уже имеющихся файлов. При повторе можно сменить метод загрузки (например, переключиться с зеркал на cookie `osu_session`) или включить/отключить режим «Без видео».
- **Стриминг событий через Server-Sent Events (SSE):** Прогресс скачивания, байтовые объёмы, смена статусов и таймеры обратного отсчёта зеркал передаются клиенту в режиме реального времени через постоянный SSE-поток (`/api/downloads/:id/events` или `/api/downloads/events`). Передача байт троттлится до 100 мс для защиты от перегрузки DOM, а смена статусов карт доставляется мгновенно. При разрыве соединения клиент автоматически переключается на резервный HTTP-поллинг без прерывания работы.
- **Сохранение состояния очереди на диск (`downloads/.state.json`):** Состояние очереди, прогресс, счётчики, списки уже скачанных наборов (`doneIds`), пропущенных и сбойных карт (`errorsById`) атомарно сохраняются на диск с троттлингом до 1 с. При перезапуске процесса сервера или компьютера незавершённые задачи автоматически восстанавливаются и безопасно переводятся в режим паузы с уведомлением «Сервер был перезапущен — задача приостановлена. Нажмите «Продолжить».». Пользователь может продолжить скачивание в один клик без повторного сканирования коллекции или перекачивания имеющихся файлов, а также повторить только карты с ошибками. При открытии веб-страницы активная задача восстанавливается даже при очистке `localStorage`.

## Интеграция с локальной директорией osu! Songs

Приложение поддерживает прямую связь с вашей установленной игрой osu!:

1. **Указание и автоопределение пути:**
   - Путь можно выбрать через нативный диалог Проводника (кнопка **«Обзор…»**) либо ввести вручную в карточке **«2. Интеграция с osu! Songs»**, а также задать через переменную окружения `OSU_SONGS_DIR` (или `OSU_PATH`).
   - Поддерживается как путь к корневой папке игры (например, `C:\Games\osu!`), так и прямой путь к `Songs` (`C:\Games\osu!\Songs`). Сервер автоматически находит и нормализует путь к каталогу песен.
   - При первом запуске сервер автоматически проверяет стандартные пути установки (`%LOCALAPPDATA%\osu!\Songs`, Program Files, `C:\Games\osu!\Songs` и другие доступные диски).
   - Настройки автоматически сохраняются в `downloads/.settings.json` и переживают перезапуск приложения.

2. **Проверка уже имеющихся в игре наборов (Skip Installed):**
   - Сервер синхронно сканирует каталог `Songs` (3 700+ папок за 2–3 мс) и кэширует уникальные ID карт.
   - В предпросмотре коллекции отображаются бейджи:
     - `В игре: X из Y` (число уже установленных наборов в коллекции);
     - Цветные метки у каждой карты: `[В игре]` (зелёный), `[Скачано]` (синий), `[Новый]`;
     - Информационные статусы (например, «Все 9 наборов уже есть в osu! Songs»).
   - При активном чекбоксе **«Проверять наличие в игре и пропускать уже имеющиеся наборы»** очередь мгновенно пропускает установленные карты, экономя интернет-трафик и дисковое пространство.
   - Оценка требуемого дискового пространства перед стартом рассчитывается строго для недостающих карт.

3. **Действия со скачанными картами (Post-download actions):**
   - **Основные методы (отображаются сразу):**
     - **«Распаковывать в Songs»**: встроенный Zero-Dependency распаковщик (`extractZip`) распаковывает `.osz` в отдельную подпапку вида `{id} {artist} - {title}` прямо внутри каталога `Songs/`, удаляя временный `.osz`. Карта сразу становится готова к игре без зависаний клиента.
     - **«Оставлять в downloads/»**: файлы сохраняются только локально в папке загрузок приложения (без изменений в игровой библиотеке).
   - **Дополнительные методы (в выпадающем блоке «Дополнительные методы»):**
     - **«Перемещать .osz в Songs»**: скачанный архив `.osz` безопасно перемещается в директорию `Songs/` (с поддержкой переноса между разными логическими дисками). При открытии игры или нажатии `F5` osu! сама импортирует карту.
     - **«Копировать .osz в Songs»**: создаёт копию `.osz` в `Songs/`, сохраняя исходный `.osz` в каталоге `downloads/`.
