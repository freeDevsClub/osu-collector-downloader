# osu!Collector Downloader

[![CI](https://github.com/kymifBSM/osu-collector-downloader/actions/workflows/ci.yml/badge.svg)](https://github.com/kymifBSM/osu-collector-downloader/actions/workflows/ci.yml)
![Node.js](https://img.shields.io/badge/node-%3E%3D20.3.0-brightgreen)
![Dependencies](https://img.shields.io/badge/runtime%20dependencies-0-blue)

> Локальное веб-приложение на Node.js для массовой загрузки коллекций osu!Collector с публичных зеркал osu!. Без аккаунта, без cookie, без сторонних runtime-зависимостей.

Приложение поднимает локальную веб-страницу, получает публичный список наборов карт из osu!Collector и скачивает `.osz` с публичных зеркал osu!. Сервер слушает только loopback-интерфейс `127.0.0.1`, поэтому веб-страница и API недоступны другим компьютерам в локальной сети.

## Возможности

- **Загрузка коллекций osu!Collector без входа в аккаунт** — прямая работа с публичным API osu!Collector.
- **Параллельная загрузка (Worker Pool)** — настраиваемый пул воркеров с индивидуальным слотом на зеркало (per-mirror concurrency) и автоматическим переключением при ошибках и лимитах (HTTP 429).
- **Режим «Без видео» (No Video)** — экономия 70–80% входящего сетевого трафика и дискового пространства.
- **Интеграция с osu! Songs** — моментальное сканирование библиотеки (3 700+ папок за 2–3 мс), пропуск уже установленных карт и автораспаковка в каталог игры.
- **Прогресс в реальном времени через SSE** — передача статусов, байтов и таймеров кулдаунов по Server-Sent Events без лишних опросов.
- **Надёжная сохранность очереди на диск** — сохранение прогресса в `data/.state.json`; после перезапуска сервера загрузка возобновляется в один клик.
- **Повтор только сбойных наборов** — докачка только проблемных карт с возможностью смены метода загрузки.
- **Zero-Dependency в runtime** — реализовано исключительно на встроенных модулях Node.js.
- **Многоуровневая безопасность** — криптографическая сессионная авторизация API, валидация Host/Origin, Sec-Fetch-Site, фильтрация SSRF и DNS Rebinding, маскирование конфиденциальных данных в структурированных JSON-логах.

## Требования

- [Node.js](https://nodejs.org/) **20.3.0 или новее** (проверено на Node.js 20, 22 и 24).

## Установка

```sh
git clone https://github.com/kymifBSM/osu-collector-downloader.git
cd osu-collector-downloader
```

Для запуска установка зависимостей не требуется (Zero-Dependency). `npm install` нужен только для инструментов разработки (TypeScript/JSDoc, ESLint, Prettier).

## Использование

Запустите приложение:

```sh
npm start
# или напрямую через Node.js
node server.js
```

В консоли будет выведен локальный адрес с одноразовым сессионным токеном, защищающим API от сторонних процессов на компьютере:

```
http://127.0.0.1:3000/?token=...
```

Откройте адрес в браузере. Чтобы переопределить порт сервера:

```sh
# Linux / macOS:
PORT=3100 npm start

# Windows PowerShell:
$env:PORT=3100; npm start
```

Для остановки нажмите `Ctrl+C`: сервер выполнит graceful shutdown, корректно завершит активные потоки и удалит временные файлы `.part`.

## Способы загрузки карт

### 1. Зеркала (по умолчанию)

Используются публичные зеркала osu! со следующим каскадным порядком переключения:

1. [`osu.direct`](https://osu.direct) — `https://osu.direct/d/{id}`
2. `Hinamizawa` — `https://mirror.hinamizawa.ai/api/v1/hinai/d/{id}`
3. [`osu!dl`](https://osudl.org) — `https://osudl.org/s/{id}`

Порядок и адреса по умолчанию заданы в [`lib/config.js`](lib/config.js). Переопределить их можно через `OSU_MIRRORS`:

```sh
# JSON-массив объектов:
OSU_MIRRORS='[{"id":"my","label":"My Mirror","url":"https://example.com/d/{id}"}]'

# Список URL через запятую:
OSU_MIRRORS="https://osu.direct/d/{id},https://osudl.org/s/{id}"
```

**Параллельная загрузка (Worker Pool) и распределение нагрузки**

- Скачивание beatmap-наборов выполняется пулом воркеров (по умолчанию 3, настраивается через `DOWNLOAD_CONCURRENCY`).
- **Лимит на зеркало (Per-mirror slot):** к конкретному зеркалу отправляется не более 1 одновременного запроса.
- **Интервал между запросами (Per-mirror delay):** между последовательными обращениями к _одному и тому же_ зеркалу выдерживается пауза `DOWNLOAD_DELAY_MS` (1.1 с), что исключает превышение лимитов и ошибки HTTP 429.
- Воркеры распределяются по доступным зеркалам со смещением (round-robin / work-stealing) и при занятости первого зеркала не блокируются, а сразу переключаются на следующее свободное.
- Для авторизованного способа `session` (напрямую с `osu.ppy.sh`) в целях безопасности аккаунта всегда принудительно используется ровно 1 воркер.

**Режим «Без видео» (No Video)**

- В блоке «Скачивание» доступен чекбокс **«Скачивать без видео»** (выбор сохраняется в `localStorage`).
- При включении к запросам загрузки добавляется параметр `?noVideo=1`.
- Режим сокращает трафик и занимаемое дисковое пространство на 70–80%, а предварительная оценка требуемого места снижается с 10 МБ до 3 МБ на набор.
- Во время активной загрузки чекбокс блокируется, а в строке прогресса отображается индикатор `· без видео`.

**Ограничения частоты запросов (HTTP 429) и кулдауны**

- При получении `429` парсится заголовок `Retry-After` (в секундах или HTTP-Date). Зеркало временно ставится на паузу (по умолчанию 60 с, максимум 15 минут), а текущая карта немедленно запрашивается со следующего зеркала.
- Такой ответ не считается ошибкой карты и не увеличивает счётчик сбоев.
- В блоке «Скачивание» отображается статус каждого зеркала («доступно» или обратный отсчёт паузы). Во время загрузки статус передаётся через постоянный SSE-поток, в режиме ожидания при наличии кулдаунов — раз в 4 с через `GET /api/mirrors`.
- Если ограничены все зеркала, сервер ожидает до 30 секунд ближайшего освобождения прямо в сетевом цикле. Если пауза больше 30 секунд, задача автоматически приостанавливается (`status: "paused"`).

**Автовозобновление**

- Приостановленная из-за кулдаунов задача автоматически возобновляется сервером в момент остывания ближайшего доступного зеркала (+1 секунда запаса). В интерфейсе отображается таймер «Автовозобновление через N с».
- Поддерживается до 8 автоматических попыток возобновления подряд (`AUTO_RESUME_MAX_ATTEMPTS`). Если лимиты не сняты, остаётся ручная кнопка **Продолжить**.
- Кнопка **Остановить** доступна всегда, позволяя прервать как активную, так и приостановленную задачу.

### 2. Cookie `osu_session` (резервный способ)

Резервный маршрут загрузки напрямую с серверов `osu.ppy.sh` для редких карт, отсутствующих на зеркалах. Находится в карточке **«3. Скачивание»** под спойлером **«Резервная авторизация: Cookie osu_session (расширенные настройки)»**.

1. Авторизуйтесь на сайте <https://osu.ppy.sh> в браузере.
2. В DevTools браузера (F12 $\to$ Application/Storage $\to$ Cookies) скопируйте значение cookie `osu_session`.
3. Раскройте блок «Резервная авторизация», вставьте значение cookie, подтвердите согласие с рисками и нажмите «Сохранить».

> [!WARNING]
> Cookie предоставляет полный доступ к вашему аккаунту osu.ppy.sh. Используйте её только в случае крайней необходимости.

**Безопасность cookie:**

- Хранится **исключительно в оперативной памяти** процесса Node.js и сбрасывается при перезапуске сервера либо по истечении TTL (до 6 часов). Значение никогда не записывается на диск.
- В браузер клиенту выставляется локальная сессионная `HttpOnly; SameSite=Strict` cookie со случайным идентификатором; оригинальное значение `osu_session` в браузер не возвращается.
- Cookie передаётся строго на домены `osu.ppy.sh`. При любых редиректах на сторонние серверы cookie сессии немедленно удаляется.
- Валидация формата отсекает посторонние символы, пробелы, кавычки и инъекции.
- В любой момент сессию можно удалить кнопкой **Удалить cookie**.

## Интеграция с osu! Songs

Приложение бесшовно интегрируется с установленной копией osu!.

### Путь к Songs

- Путь выбирается через системный диалог Проводника (кнопка **«Обзор…»**), вводится вручную в карточке **«2. Интеграция с osu! Songs»** или задаётся переменной `OSU_SONGS_DIR` (или `OSU_PATH`).
- Поддерживается как корень игры (`C:\Games\osu!`), так и сам каталог `Songs` (`C:\Games\osu!\Songs`) — сервер нормализует путь автоматически.
- При первом запуске проверяются типовые пути (`%LOCALAPPDATA%\osu!\Songs`, Program Files, `C:\Games\osu!\Songs` и корни других логических дисков).
- Настройки сохраняются в `data/.settings.json` (с обратной совместимостью с файлами в каталоге загрузок) и переживают перезапуски.

### Пропуск уже установленных наборов

- Сервер сканирует каталог `Songs` (3 700+ папок за 2–3 мс) и кэширует ID наборов карт.
- В предпросмотре коллекции отображаются счётчик `В игре: X из Y`, статусные бейджи у карт (`[В игре]` — зелёный, `[Скачано]` — синий, `[Новый]`) и сводные уведомления («Все N наборов уже есть в osu! Songs»).
- При активном чекбоксе **«Проверять наличие в игре и пропускать уже имеющиеся наборы»** установленные карты пропускаются, а расчёт требуемого места на диске учитывает только недостающие наборы.

### Действия после загрузки

| Метод                         | Что делает                                                                                                                              |
| :---------------------------- | :-------------------------------------------------------------------------------------------------------------------------------------- |
| **Распаковывать в Songs**     | Встроенный распаковщик (`extractZip`) раскладывает `.osz` в папку `{id} {artist} - {title}` внутри `Songs/` и удаляет временный `.osz`. |
| **Оставлять в downloads/**    | Файлы остаются только в папке загрузок приложения, игровая библиотека не затрагивается.                                                 |
| **Перемещать .osz в Songs** ¹ | Архив перемещается в `Songs/` (в том числе между логическими дисками). osu! импортирует его при запуске или по клавише `F5`.            |
| **Копировать .osz в Songs** ¹ | Копия `.osz` помещается в `Songs/`, оригинал сохраняется в `downloads/`.                                                                |

¹ Доступны в выпадающем списке «Дополнительные методы».

## Надёжность и безопасность

**Безопасность**

- **SSRF и DNS Rebinding:** При редиректах зеркал проверяется целевой хост через асинхронный `dns.lookup` с валидацией всех IP-адресов. Запрещены приватные подсети (RFC 1918), loopback (`127.0.0.0/8`, `::1`), link-local / облачные метаданные (`169.254.169.254`, `fe80::/10`), CGNAT (`100.64.0.0/10`) и любые порты, кроме 443.
- **CSRF и Fetch Metadata:** Запросы проверяются по заголовкам `Host`, `Origin` и W3C `Sec-Fetch-Site`; кросс-сайтовые запросы отклоняются с кодом HTTP 403.
- **Токен API и аутентификация:** Мутирующие запросы и Server-Sent Events защищены локальным токеном авторизации API. Флаг `DISABLE_API_TOKEN=1` полностью отключает проверку и сопровождается предупреждением `security.api_token_disabled` в логах (предназначен только для изолированных сред разработки и тестов).
- **Маскирование секретов:** Cookie, Client Secret и токены автоматически регистрируются в механизме санитизации и заменяются на `[redacted]` в консоли и ошибках. Логи пишутся в структурированном JSON.

**Надёжность**

- **Атомарная запись и верификация ZIP:** Набор скачивается во временный `{setId}.{jobId}.part`. Перед переименованием в `.osz` проверяется сигнатура EOCD (End of Central Directory) архива ZIP / ZIP64. Повреждённые файлы и HTML-страницы ошибок отбрасываются.
- **Изоляция и очистка stale part-файлов:** Временные файлы содержат уникальный `jobId`, исключая коллизии между параллельными задачами, а устаревшие сиротские файлы безопасно удаляются по таймауту.
- **Контроль дискового пространства:** Перед запуском очереди сервер оценивает недостающий объём данных и проверяет доступное место через `statfs`. Если диск переполнится в процессе, очередь корректно останавливается без потери готовых файлов.
- **Дедупликация и кэш osu!Collector:** Снимки коллекций кэшируются на 10 минут, параллельные запросы объединяются (`in-flight join`), исключая лишнюю нагрузку на API osu!Collector.
- **Мгновенный старт и ленивые метаданные:** Список `setIds` и карточка коллекции загружаются за ~150–300 мс; кнопка скачивания доступна сразу, а детальные метаданные карточек карт догружаются в фоне без скачков интерфейса.
- **Повтор только сбойных наборов:** При наличии сбоев (`failed > 0`) доступна кнопка **«Повторить ошибки (N)»** (`POST /api/downloads/:id/retry-failed`), ставящая в очередь только проблемные карты с возможностью смены настроек.
- **SSE-стриминг прогресса:** События загрузки транслируются по постоянному каналу `/api/downloads/:id/events` с троттлингом байтов до 100 мс и мгновенной доставкой смены статусов. При разрыве соединения интерфейс прозрачно переключается на HTTP-поллинг.
- **Сохранение состояния очереди на диск:** Состояние очереди, счётчики, `doneIds` и `errorsById` атомарно сохраняются в каталог данных (`data/.state.json`). После перезапуска сервера незавершённые задачи восстанавливаются в режиме паузы, продолжаясь в один клик.

### Архитектурная модель: Single-Instance State

Приложение спроектировано как **локальная однопользовательская настольная утилита (Single-Instance Application)**:

- **Состояние в памяти процесса:** Очереди задач (`jobs`, `activeJob`), активные сессии (`sessions`), кэш метаданных и библиотеки `Songs` хранятся в памяти управляющего процесса Node.js (in-memory single instance).
- **Масштабирование:** Приложение не предназначено для запуска в многопроцессном режиме (Worker Threads / кластеризация / PM2 cluster) с общим состоянием. Горизонтальное масштабирование или разделение состояния между несколькими процессами потребует выноса хранилища (например, в Redis или внешнюю СУБД).
- **Изоляция в тестах:** Для обеспечения независимости тестов модули предоставляют явные функции сброса состояния (`resetSettingsForTest()`, `resetMirrorsForTest()`, `clearSaveStateTimer()` и изолированные переменные окружения `DATA_DIR` / `DOWNLOADS_DIR`).
- **Персистентность:** Сохранение между перезапусками обеспечивается файловой персистентностью в `DATA_DIR/.state.json` с атомарной записью.
